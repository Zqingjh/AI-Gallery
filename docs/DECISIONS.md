## ADR-LITE-019 真人试用视频首帧封面组件

- 状态：接受
- 日期：2026-07-15
- 决策：按用户明确授权，仅 Windows x64 的本项目安装包携带独立运行的 FFmpeg 7.1.5 LGPL v3 二进制；不搜索 PATH、不接受导入流程传入的外部命令。构建锁定 BtbN 月末长期保留发布 `autobuild-2026-06-30-13-34`：ZIP SHA-256 为 `ec1c6ae03fab10f316344973f83c549b4b662ec3d73f1658353ab1587f4cf727`，提取的 `ffmpeg.exe` 为 108,298,752 B，SHA-256 为 `e46b5b83f8a5ff3790cc27ad1d8947146c0a22661f0337f701769f6d75bf998a`。二进制与下载临时目录不进入 Git，NSIS 从 Tauri resource 打包该文件；上游月末构建保留两年，须在 2028-06-30 前重新锁定并验收新构建或迁移到长期受控镜像。
- 行为：MP4 导入完成并写入作品记录后，单线程依次提取第 0 毫秒画面并复用既有 PNG 校验、唯一文件名、封面事务和旧封面清理逻辑。单个视频提取失败只显示“部分视频未能生成预览封面”，绝不撤销已成功导入的媒体或作品。
- 资源与安全：复用已有参数数组启动、无窗口、30 秒超时、终止回收、拒绝符号链接/reparse point、10 MiB PNG 与 40 MP 像素上限；导入作业本身仍全局串行，封面提取不会超过 1 个并发进程。
- 许可：FFmpeg 构建启用 `--enable-version3`，其随附许可证为 LGPL-3.0-or-later。`THIRD_PARTY_NOTICES.md` 记录精确构建、源码和构建脚本地址；若对外分发安装包，发布者必须另行满足 FFmpeg 的源码、构建说明与许可证交付义务。
- 体积与替代：内置二进制约 103.3 MiB，当前 NSIS 安装包 38,965,317 B（约 37.16 MiB）；相对未捆绑时期显著增长，但属于用户已批准的体积例外。替代方案是继续要求用户选择外部 FFmpeg，或把组件改成按需下载；未采用是因为导入视频与恢复默认封面需要开箱即用、可校验且不依赖系统 `PATH`。高级关键帧工具仍保留用户显式选择外部 FFmpeg 的路径。
